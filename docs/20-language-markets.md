# 20. 언어·시장 확장 로드맵

- 기준일: 2026-11-16 (Dan 지시: 런칭은 영어만, 이후 학구열이 강한 나라 순으로 확장)
- 담당: 외부인 레인(사이트·시장). 언어 팩 구조는 `04` 4.13, 배역 팩은 `packages/content/src/npc-cast.ts`(대화 레인)와 맞춥니다.
- `가정`이라고 적은 것은 실측 전 판단입니다. 숫자에는 모두 출처를 붙였고, 출처가 없는 숫자는 쓰지 않았습니다.

## 1. 두 언어 축을 나눕니다

| 축 | 뜻 | 지금 값 | 어디에 쓰이나 |
|---|---|---|---|
| `target_lang` | 아이가 **배우는** 말. NPC가 말하고, 문장 뱅크·채점·음성이 이 말입니다 | `en` | 문장 뱅크, 채점, 인식(STT), NPC 음성(TTS), 배역 팩의 원어민 이름 |
| `l1` | 아이와 보호자가 **읽는** 말(모국어). 화면 글자·설명·힌트·리포트가 이 말입니다 | `ko` | 사이트, 월드 UI 문자열, 단어 뜻 힌트, 혼용 발화 사전, 보호자 리포트, 결제 화면 |

- 언어 팩 하나가 두 축의 조합 하나입니다. 지금은 `en-ko` 하나입니다(`packages/content/src/lang-en-ko.ts` `LANG_PACK_MANIFEST`).
- 데이터 모델은 이미 둘을 나눠 두었습니다. `players.l1`, `players.target_lang`(`02` 데이터 모델)입니다.
- **확장은 대부분 `l1`을 늘리는 일입니다.** 일본·대만·베트남 아이도 영어(`target_lang=en`)를 배웁니다. 늘어나는 것은 화면 언어, 뜻 힌트, 결제입니다. 문장 뱅크·채점·음성은 영어 그대로 다시 씁니다.
- `target_lang`을 늘리는 일(예: 영어권 아이가 한국어·중국어를 배움)은 별도 축입니다. 문장 뱅크·채점·음성·배역 팩을 그 말로 새로 만들어야 하고, 원어민 검수(`04` 4.13)를 거칩니다.

### 1.1 배역 팩과의 관계

- 배역 팩은 `target_lang`마다 하나입니다. 영어 팩에는 Hannah, Mia, Luna, Toby, Chef Leo 가 있고, 이름은 그 말의 원어민 아이가 아는 이름입니다(`npc-cast.ts` 머리말).
- 팩 안의 `nameKo`·`nameKoShort`는 **`l1` 표시 이름**입니다. `l1`이 늘면 `nameKo`를 `label[l1]`(예: `{ ko: { full: '카페 주인 해나', short: '해나' }, ja: { full: 'カフェのハンナ', short: 'ハンナ' } }`)로 바꿔야 합니다. 이 변경은 대화 레인 몫이고, 두 번째 `l1`을 열 때 같이 합니다(`가정`: 그 전에는 지금 구조를 유지).
- 사이트는 이름을 직접 쓰지 않고 팩에서 읽습니다(#57, `apps/web/src/site/copy.ts` `castKo`).

## 2. 다음 시장 순서

### 2.1 판단 기준

학구열은 한 숫자로 비교할 수 없습니다. 그래서 세 가지를 같이 봅니다.

1. **사교육 강도**: 가계가 학교 밖 학습에 쓰는 돈과 참여율.
2. **영어 격차**: EF EPI 2024 점수. 낮을수록 영어 말하기 수요가 큽니다.
3. **닿을 수 있는가**: 앱 스토어와 결제 수단이 있는가, 사이트와 월드가 그 나라에서 바로 열리는가.

`target_lang=en` 확장에서는 영어 실력이 이미 높은 곳(싱가포르 EF 609, 3위)을 뒤로 둡니다. 사교육 강도가 높아도 영어 말하기 수요는 작기 때문입니다.

### 3.2 음성 (확인한 것과 확인할 것)

- NPC 음성은 Workers AI Deepgram Aura를 씁니다(`npc-cast.ts` `NpcVoice`). Cloudflare 모델 페이지에는 Aura 지원 언어가 적혀 있지 않습니다. 영어 외 `target_lang`을 열 때 실측합니다.
- MeloTTS(대체 엔진)는 `lang` 값을 받지만 문서에 예시가 `en`·`fr`뿐입니다. `ja`·`zh`·`ko` 지원은 실측 전입니다(`가정`).
- `target_lang=en` 확장(1~4순위)에서는 음성 작업이 필요 없습니다. NPC는 계속 영어로 말합니다.

### 3.3 결제·스토어 (`가정`, 실측 전)

- 아이 화면에는 가격·결제·기한이 없습니다(AGENTS.md 4.9). 결제는 보호자 화면과 사이트 요금 페이지에만 있으므로, 번역·통화 작업도 그쪽만 합니다.
- 나라마다 가격표를 따로 둡니다. 원화 가격을 환율로 바꾸지 않고 그 나라 사교육비 수준을 봅니다(베트남은 낮게 시작).
- 결제 수단 후보는 일본(앱 스토어, 카드, 편의점 결제), 대만·홍콩(앱 스토어, 카드), 베트남(앱 스토어, 전자지갑)입니다. 어느 PG를 쓸지는 운영 레인이 실측해 결정 카드로 올립니다(돈이 걸린 일).

### 3.4 순서를 다시 정하는 고리

- 사이트 카운터(`/v1/site/event`, 쿠키 없음)에 나라 코드(Cloudflare `cf-ipcountry`)와 브라우저 언어(`Accept-Language` 첫 값) 묶음을 더합니다. 개인 식별 없이 일·페이지·나라 단위로만 셉니다.
- 매주 나라별 `try_start`·`send_to_parent`·보호자 전환을 보고, 2.3의 순서를 다시 정합니다. 데이터 → 판단 → 다음 언어 → 결과의 고리입니다.
- 이 일은 외부인 레인이 다음 작업으로 맡습니다(`docs/spec-coverage.json`에 항목을 올려 상태를 관리).

## 4. 사이트 i18n 경로 설계 (구현은 두 번째 `l1`을 열 때)

### 4.1 경로

| 언어 | 경로 | 비고 |
|---|---|---|
| 한국어 (`ko`) | `/`, `/parents`, `/play` … 지금 그대로 | 런칭 언어. 이미 퍼진 링크·카카오톡 미리보기·검색 색인을 지킵니다 |
| 일본어 (`ja`) | `/ja/`, `/ja/parents`, `/ja/play` … | 하위 경로. 도메인을 나누지 않습니다(한 Worker, 한 인증서, 한 색인) |
| 번체 중국어 (`zh-Hant`) | `/zh-hant/…` | 대만·홍콩 공용. 홍콩만 다른 문구가 필요하면 `/zh-hk/`를 그때 추가 |
| 베트남어 (`vi`) | `/vi/…` | |
| 영어 UI (`en`, 먼 미래) | `/en/…` | `target_lang`이 영어가 아닌 팩을 영어권에 팔 때만 |

- **학습 페이지**: `/learn/order-a-drink`의 영어 문장은 언어와 무관합니다. 설명만 `l1`로 바꿉니다. 그래서 `/ja/learn/order-a-drink`처럼 같은 슬러그를 씁니다.
- **공유 링크는 언어 없는 경로**입니다. `/s/<token>`(쇼룸), `/r/<token>`(리포트), `/pass`, `/world/`(월드)가 그렇습니다. 같은 링크를 받은 사람마다 화면 언어는 4.3의 순서로 고릅니다. 월드 안 UI 언어는 경로가 아니라 플레이어 프로필의 `l1`입니다.
- 앱 화면(`/join`, `/director`, `/family` 등)도 경로에 언어를 넣지 않습니다. 로그인한 사람의 `l1` 설정을 따릅니다.

### 4.2 검색과 미리보기

- 각 언어 페이지는 자기 `<link rel="canonical">`과 `hreflang` 대체 링크 전체(`ko`, `ja`, `zh-Hant`, `vi`)를 가집니다. `x-default`는 한국어 루트로 둡니다(`가정`: 영어 UI가 생기면 `/en/`로 옮김).
- sitemap은 언어마다 `<xhtml:link rel="alternate" hreflang>`을 붙입니다(`tools/prerender-site.mjs`가 생성).
- `og:locale`(`ko_KR`, `ja_JP`, `zh_TW`, `vi_VN`)과 `og:locale:alternate`를 넣습니다. 공유 그림(`/og/*.jpg`)은 그림 안 글자를 빼고 실제 화면만 두었으므로(#34) 언어마다 다시 찍지 않아도 됩니다. 단 월드 화면 속 `l1` 글자(이름표·대화창)는 그 언어로 찍은 캡처가 필요합니다(`tools/site-captures.mjs`에 `l1` 인자 추가).

### 4.3 언어 고르기

1. 경로에 언어가 있으면 그 언어.
2. 없으면(루트) 한국어를 보여 줍니다. **자동 리다이렉트는 하지 않습니다**: 검색 로봇과 미리보기 수집기는 언어 헤더가 일정하지 않아, 리다이렉트하면 잘못된 언어가 색인됩니다.
3. 브라우저 언어(`Accept-Language`)가 지원 언어이고 경로 언어와 다르면, 화면 위에 "日本語で見る" 같은 띠를 한 줄 띄웁니다. 닫으면 그 기기에서 다시 묻지 않습니다(localStorage, 실패해도 무시).
4. 사용자가 고른 언어는 쿠키가 아니라 경로로만 유지합니다. 쿠키 배너가 필요 없습니다(`14` §11: 쿠키 없음).

### 4.4 코드 구조

- 문구 파일을 언어별로 나눕니다: `apps/web/src/site/copy.ts` → `copy/ko.ts`, `copy/ja.ts` …, 같은 키·같은 타입. 타입이 키 누락을 막고, 시험이 언어별 파일의 키 집합이 같은지 확인합니다.
- `routes.ts`의 `parseSitePath`가 언어 접두를 먼저 떼고 `{ locale, page }`를 돌려줍니다. `prerenderPaths()`는 지원 언어 × 페이지로 늘어납니다.
- `SITE_PAGES`의 공유 그림·색인 여부는 언어와 무관하게 페이지마다 하나로 둡니다.
- Worker(`apps/edge`)는 바꿀 것이 없습니다. 언어별 페이지도 정적 파일이고, `run_worker_first`의 `/*` 규칙과 HTML 압축(#50)을 그대로 탑니다.
- 아이 화면 금지 규칙(가격·결제·기한 없음)과 '게임' 금지어 시험은 언어마다 그 말의 금지어 목록으로 확장합니다(`21` 용어집).
